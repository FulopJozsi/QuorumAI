# QuorumAI

QuorumAI — это модульная система оркестрации мультиагентного ИИ, работающая на собственном сервере и построенная на LangGraph. Она полностью работает в Docker, подключается ко всем основным платформам обмена сообщениями, поддерживает голосовое взаимодействие, управление умным домом и имитирует многоролевую ИИ-«компанию» с долгосрочной памятью и автономным выполнением задач.

![Python 3.11](https://img.shields.io/badge/Python-3.11-blue.svg) ![Docker](https://img.shields.io/badge/Docker-Compose-2496ED.svg)

---

## Что такое QuorumAI

QuorumAI превращает один или несколько LLM в команду ИИ-агентов, которая умеет:

- Отвечать на вопросы, читать новости и управлять устройствами умного дома — через микрофон, Telegram, Matrix, Discord, Slack, Signal, WhatsApp, Viber или IRC.
- Делегировать работу между специализированными ролями (CEO, разработчик, продажи) и поддерживать долгосрочную память между сессиями с помощью векторного поиска Qdrant.
- Автономно выполнять задачи через планировщик heartbeat, запрашивать подтверждение от человека при необходимости (HITL) и предоставлять каждую внешнюю возможность как MCP-сервер (Model Context Protocol).

Всё настраивается в YAML. Для смены модели, добавления агентов или подключения новых инструментов не нужно менять код.

## Быстрая установка

### Одна команда (рекомендуется)

Bootstrap-установщик проверяет наличие Python 3 и Docker, устанавливает их при необходимости, затем запускает интерактивный установщик QuorumAI.

**Linux / macOS:**
```bash
curl -fsSL https://raw.githubusercontent.com/fulopjozsef86/QuorumAI/main/install.sh | bash
```

**Windows (PowerShell — запустить от имени Администратора):**
```powershell
irm https://raw.githubusercontent.com/fulopjozsef86/QuorumAI/main/install.ps1 | iex
```

Или загрузите `install.bat` / `install.ps1` из репозитория и дважды щёлкните.

> **Примечание:** На Linux bootstrap устанавливает Docker Engine из официального репозитория Docker (apt/dnf/yum в зависимости от дистрибутива) и добавляет пользователя в группу `docker`. Требуется выйти из системы и войти снова. На macOS и Windows устанавливает Docker Desktop и предлагает запустить его перед продолжением.

Клонируйте репозиторий и запустите интерактивный установщик напрямую — pip и дополнительные зависимости не нужны:

## Функции

### Основная оркестрация

- **Среда выполнения LangGraph** — граф агентов на конечном автомате, нативное HITL-чекпоинтирование, `AsyncPostgresSaver`.
- **FastAPI HTTP API** — `POST /invoke`, `GET /health`, стриминг, приёмник вебхуков, ретрансляция push-уведомлений.
- **agents.yaml** — объявляйте агентов в YAML: имя, роль, провайдер, модель, путь к системному промпту, инструменты.
- **Горячая перезагрузка** — `POST /agents/reload` перезагружает `agents.yaml` без перезапуска контейнера.
- **Протокол инструментов MCP** — каждая внешняя возможность является MCP-сервером; агенты обнаруживают инструменты автоматически.
- **Векторная память Qdrant** — гибридный семантический + BM42-лексический поиск, многоязычные E5-Large-эмбеддинги, коллекции в разрезе агентов, косинусная дедупликация, MMR-диверсифицированный поиск.
- **Ночная консолидация памяти** — запланированное «задание-сон» дистиллирует историю сессий PostgreSQL в долгосрочные факты Qdrant; объединяет прогрессии, удаляет устаревшие эфемерные записи; состояние отслеживается в PostgreSQL.
- **PostgreSQL** — checkpointer `AsyncPostgresSaver` + таблицы задач и комментариев.
- **Граф знаний** — FalkorDB (совместим с Redis), Cypher-запросы в разрезе пользователей, автоматическое извлечение сущностей.

### Симуляция мультиагентной компании

- Ролевые агенты: CEO, разработчик, продажи и любая пользовательская роль.
- Агент-диспетчер автоматически направляет входящие запросы к нужному специалисту.
- Пайплайн-агенты: циклы планировщик → исполнитель → ревизор с общим состоянием.
- **Автономные (Deep) агенты** — установите `deep: true` для любого агента или стадии пайплайна, чтобы активировать встроенный ReAct-цикл LangGraph. Агент самостоятельно планирует, выполняет и итерирует — вызывает инструменты до завершения задачи или достижения опционального лимита вызовов (`deep_max_steps`, 0 = без ограничений). Настраивается на уровне агента и стадии; переключатель доступен в GUI Agent Builder.
- Библиотека навыков: Markdown-файлы навыков, ленивая загрузка на агента, маркетплейс сообщества для обмена.
- Общее рабочее пространство: агенты могут читать и писать в общую файловую область.
- **Инструменты администрирования** — агенты с ролью `admin` могут создавать и удалять агентов, навыки, MCP-серверы, cron-задачи и расписания heartbeat в реальном времени через инструменты `system-admin`. Каждое действие записи требует подтверждения HITL.

### Управление задачами и автономность

- Канбан-доска с подзадачами и комментариями (на PostgreSQL).
- Планировщик heartbeat: агенты автоматически берут ожидающие задачи (по умолчанию каждые 5 минут).
- Автономное выполнение с HITL-воротами согласования (Telegram `/approve`, кнопки GUI).
- Push-уведомления: Telegram, Home Assistant `notify`, веб-пуш (VAPID). В задачах можно указать поле `notify_channel`, чтобы сообщение о завершении всегда попадало на нужный бридж вне зависимости от того, в какой сессии была создана задача. Агенты могут вызвать `list_notify_channels()`, чтобы узнать доступные каналы в реальном времени.

**Многодневные задачи** — рекомендуемый шаблон для длительной работы, занимающей часы или дни:
1. Создайте задачу с названием и описанием (через чат, Telegram или канбан-доску GUI).
2. Агент (или вы) вызывает `set_subtasks`, чтобы разбить её на именованные шаги.
3. Каждый запуск heartbeat берёт следующую ожидающую подзадачу, выполняет её и останавливается — отдельные LLM-сессии остаются короткими и сфокусированными.
4. Прогресс, решения и промежуточные результаты хранятся в комментариях к задаче, так что каждый следующий запуск имеет полный контекст произошедшего.
5. Когда все подзадачи выполнены, агент закрывает задачу и отправляет уведомление о завершении.

Этот шаблон работает без изменений кода — он построен на существующих инструментах задач (`set_subtasks`, `get_next_subtask`, `complete_subtask`), к которым имеет доступ любой агент с источником инструментов `tasks`.

### Надзор безопасности (Квадрумвират)

Опциональный пер-агентный слой, проверяющий каждый рискованный вызов инструмента перед исполнением. Включается флагом `guardian: true` в `agents.yaml`; агенты без этого флага не затрагиваются.

- **Guardian** — изолированный вызов LLM (без инструментов), оценивающий имя и аргументы инструмента и возвращающий: `NONE` (продолжить), `SOFT VETO: причина` (требуется решение человека) или `HARD VETO: причина` (немедленная блокировка).
- **Арбитр** — активируется при SOFT VETO; генерирует Markdown-аналитический отчёт и приостанавливает граф через LangGraph `interrupt()`. Оператор одобряет или отклоняет через Telegram `/approve` или GUI — тот же поток, что и HITL.
- **Историк** — задание heartbeat, читающее аудит-журнал Guardian из памяти и записывающее структурированный отчёт в таблицу PostgreSQL `historian_reports`.
- **Классификация рисков** — MCP-серверы помечаются в `mcps.yaml` как `risk: low` или `risk: high`. Инструменты памяти, задач и одобрения всегда исключены из проверки.

```yaml
# agents.yaml
agents:
  - name: ceo
    guardian: true
    guardian_provider: anthropic        # необязательно — наследует провайдера агента если пусто
    guardian_model: claude-haiku-4-5-20251001
    arbiter_provider: anthropic
    arbiter_model: claude-sonnet-4-6
```

```yaml
# mcps.yaml
servers:
  - name: playwright
    risk: high        # все инструменты playwright требуют одобрения Guardian
  - name: hu-tools
    risk: low         # погода, новости — передаются без проверки
```

Эндпоинт `/guardian/log` возвращает живой аудит-журнал (последние 1 000 решений).

### Аутентификация и мультиарендность

| Режим | Описание |
|---|---|
| `AUTH_MODE=none` | Открытый — без аутентификации (по умолчанию, для локального использования) |
| `AUTH_MODE=local` | Bearer-токен; пользователи задаются в `LOCAL_USERS=user1:pass1,...` |
| `AUTH_MODE=sso` | Keycloak OIDC/JWT или любой OIDC-провайдер (Auth0, Okta, Authelia, …) |

**Изоляция по пользователю.** В многопользовательском режиме память и граф
знаний каждого пользователя разделены: долговременная память попадает в его
собственную коллекцию Qdrant, а граф — в собственный `scope`. Чтение видит свои
данные и общий слой, курируемый администратором, но никогда данные другого
пользователя. Ночное обслуживание также выполняется **для каждого пользователя
отдельно**.

Принимает подписанные вебхуки от: GitHub, Gitea, Drone CI, Grafana, n8n, Slack, ERPNext, Twenty CRM, Zammad, Tiledesk, Uptime Kuma, Wekan, Umami, Duplicati, BorgWarehouse.

### Резервное копирование и сохранение конфигурации

Все данные среды выполнения хранятся в `data/` в виде bind-монтирований; вся конфигурация в YAML-файлах — никакого скрытого состояния внутри контейнеров.

**Создание резервной копии** (включает `.env` + `data/`):

```bash
sudo python3 backup.py backup                 # интерактивно, автоматическое имя файла
sudo python3 backup.py backup /srv/backup.tgz # явный путь вывода
```

**Восстановление**:

```bash
python3 backup.py restore /srv/backup.tgz          # восстановить в текущую директорию
python3 backup.py restore /srv/backup.tgz /opt/qai # восстановить в указанную директорию
```

На Linux / macOS запускать с `sudo` для сохранения владельцев файлов. На Windows не требуется.

## Голос

### Бридж микрофона (локальный микрофон)

Профиль Compose: `mic`

- openWakeWord — настраиваемое слово-будильник (по умолчанию: "Ok Szif").
- Wyoming Whisper — локальный STT, без облака.
- Wyoming Piper — локальный TTS.
- Монтирование сокета PulseAudio для Linux-десктопов.

**Примечания по платформам:**

- **Linux** — установщик определяет ваш UID и автоматически монтирует правильный сокет PulseAudio (`/run/user/<uid>/pulse`).
- **macOS / Windows** — Docker Desktop не пробрасывает аудиоустройства. Установщик записывает конфигурацию PulseAudio TCP. Настройте PulseAudio в режиме TCP перед запуском контейнера mic:
  - macOS: `brew install pulseaudio && pulseaudio --load=module-native-protocol-tcp --exit-idle-time=-1 --daemon`
  - Windows (WSL2): `sudo apt install pulseaudio && pulseaudio --load=module-native-protocol-tcp --exit-idle-time=-1 --start`
  - Windows (нативный): загрузите PulseAudio для Windows, раскомментируйте `module-native-protocol-tcp` в `default.pa`, разрешите порт 4713 в брандмауэре.

### Home Assistant Voice PE

Профиль Compose: `ha`

QuorumAI регистрируется как агент разговора внутри Home Assistant. HA Assist обрабатывает обнаружение слова-будильника, Whisper STT и Piper TTS на стороне HA; QuorumAI отвечает за логику рассуждений и вызовы инструментов.

### Инструменты STT и TTS (вызываемые агентами)

Профиль Compose: `stt-tts`

Предоставляет Whisper и Piper как HTTP API, которые агенты могут вызывать как инструменты `system-stt` и `system-tts`.

### Выбор профилей

Задайте профили в `.env`, чтобы простой `docker compose up -d` работал без флагов:

```env
COMPOSE_PROFILES=orchestrator,memory,mcp,postgres,telegram,gui
```

Или передайте явно:

```bash
docker compose --profile orchestrator --profile memory --profile gui up -d
```

Доступные профили: `orchestrator`, `memory`, `mcp`, `postgres`, `telegram`, `ha`, `mic`, `gui`, `stt-tts`, `mcp-manager`, `playwright`, `joplin`, `auth`, `email`, `matrix`, `discord`, `irc`, `whatsapp`, `slack`, `signal`, `viber`, `graph`

### Пересборка после изменений исходного кода

```bash
# Пересобрать только изменённый сервис:
docker compose build orchestrator

# Перезапустить без остановки других контейнеров:
docker compose up -d --no-deps orchestrator
```

### Структура директории данных

```
data/
  qdrant/        # Векторы Qdrant
  postgres/      # Данные PostgreSQL
  workspace/     # Файловое рабочее пространство на агента
  whisper/       # Кэш моделей Whisper
  piper/         # Голосовые файлы Piper
  ...
```

Всё под `data/` занесено в `.gitignore`. Резервная копия этой директории сохраняет всё постоянное состояние.

## CRM-интеграция

CRM MCP (`mcps/crm/`) предоставляет единый интерфейс для нескольких CRM-систем через сменную адаптерную архитектуру. Агенты используют одни и те же инструменты независимо от бэкенда.

**Поддерживаемые адаптеры:**

| Адаптер | Система | Тип |
|---|---|---|
| `minicrm` | MiniCRM (лидер венгерского рынка) | Полный |
| `hubspot` | HubSpot CRM | Полный |
| `pipedrive` | Pipedrive | Полный |
| `billingo` | Billingo (выставление счетов) | Только чтение |
| `szamlazzhu` | Számlázz.hu (выставление счетов) | Только чтение |
| `salesautopilot` | SalesAutopilot (HU маркетинговая автоматизация) | Полный |

**Доступные инструменты:** `search_entities`, `get_entity`, `create_entity`, `update_entity`, `add_note`, `get_timeline`, `link_entities`, `get_related`, `emit_event`, `list_entity_types`

**Быстрый старт:**
```env
CRM_ADAPTER=minicrm
MINICRM_SYSTEM_ID=12345
MINICRM_API_KEY=your-key
```

```bash
docker compose --profile crm up -d
```

Добавьте `crm` в список `tools:` агента в `agents.yaml`, чтобы дать ему доступ к CRM.

## jog.gov.hu MCP — Поиск венгерского законодательства

MCP jog.gov.hu (`mcps/jog-hu/`) предоставляет венгерскую правовую информацию ИИ-агентам в двух режимах развёртывания:

**Режим Docker** (всегда работает, Playwright не требуется):

| Инструмент | Описание |
|---|---|
| `search_njt_laws(keywords)` | Поиск по ключевым словам на njt.jog.gov.hu — возвращает названия законов и URL |
| `get_law_text(law_id, section)` | Полный или частичный текст закона с njt.hu (например, `"2012. évi I. törvény"`, раздел `"69"`) |
| `list_recent_laws(category, days)` | Недавние законы из RSS-ленты Magyar Közlöny |

**Режим хоста** (ИИ-поиск, требует запуска `host_server.py` на хост-машине):

| Инструмент | Описание |
|---|---|
| `search_law(question)` | Вопрос на естественном языке → ответ ИИ + ссылки на законы (jog.gov.hu) |

reCAPTCHA v3 оценивает сессии прежде всего на основе **репутации IP-адреса**. IP-адреса Docker-контейнеров и облачных/VPS-серверов классифицируются как адреса датацентров и получают низкий балл доверия — независимо от патчей отпечатка браузера. Домашняя или офисная машина на **жилом IP-адресе** получает достаточно высокий балл для прохождения проверки. Графический дисплей **не требуется** — браузер работает в безголовом режиме; наличие дисплея не имеет значения.

**Быстрый старт (Docker-инструменты — всегда работают):**
```bash
docker compose --profile jog-hu up -d
```

**Запуск хост-сервера (ИИ-поиск — требуется жилой IP-адрес):**
```bash
# Работает на: домашнем/офисном настольном ПК или ноутбуке (Windows, macOS, Linux)
# НЕ работает на: облачных/VPS-серверах (IP-адреса датацентров блокируются reCAPTCHA)
# Графический дисплей НЕ требуется — работает в безголовом режиме

pip install mcp fastmcp httpx playwright playwright-stealth
playwright install chromium

python3 mcps/jog-hu/host_server.py --background   # запустить демон, порт 4312
python3 mcps/jog-hu/host_server.py --stop          # остановить демон
```

**Добавьте в `mcps.yaml`:**
```yaml
- name: jog-hu
  url: http://jog-hu-mcp:4302/mcp/
  description: Hungarian legal search (njt.hu)

# Опционально — только если запущен host_server.py:
- name: jog-hu-host
  url: http://host.docker.internal:4312/mcp/
  description: Hungarian legal AI search (jog.gov.hu)
```

Добавьте `jog-hu` (и опционально `jog-hu-host`) в список `tools:` агента в `agents.yaml`.
